## Summary
The codebase follows a disciplined component/hook/lib layering with consistent defensive SDK-guarding and a documented 'pre-built component' philosophy, but it carries scars from an AI-scaffold workflow: a stale packet-era contract file (contract.ts) still injects a conflicting `Record`/`Workplace`/`RouteState` type family alongside the real ones in types.ts, and the payroll engine itself appears to have two divergent implementations (`calcDaily` vs `calculateDailyPayroll`) used by different features. Beyond those structural risks, there's a fair amount of copy-pasted date/format/toast boilerplate across page files that should be centralized.

## Issues
### Critical
- [duplication] src/lib/payrollDaily.ts contains two separate implementations of 'compute one day's pay': `calcDaily` (returns DailyPay: workedMinutes/basePay/nightPay/total, used by Home, Records, RecordForm, RecentRecordsCard) and `calculateDailyPayroll` (returns the contract.ts-shaped PayrollEntry: dailyWages/adjustments, imported and used by lib/analysis.ts for the underpaid-analysis feature). Two independently-evolving calculation paths for the same domain concept risk producing different numbers for the same record in different screens. — Files: src/lib/payrollDaily.ts, src/lib/analysis.ts, src/lib/payrollMonthly.ts / Fix: Pick one payroll calculation function as the single source of truth (likely calcDaily/DailyPay, since it's the actively used one), have analysis.ts consume it, and delete the parallel PayrollEntry-based calculateDailyPayroll path.
- [naming] The `Workplace` and `WorkRecord`/`Record` entities are defined three incompatible ways: contract.ts's `Workplace` (baseHourlyRate/isActive) and `Record` (hoursWorked/hourlyRate), payrollDaily.ts's local `Workplace` (wage/isFiveOrMore) and `WorkRecord` (startTime/endTime/breakMinutes only), and lib/types.ts's full `Workplace`/`WorkRecord` (hourlyWage/payday/taxType/colorToken, etc.). Because contract.ts exports a type literally named `Record`, other files are forced to write `globalThis.Record<K,V>` to get the built-in utility type back. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/payrollDaily.ts, src/lib/analysis.ts / Fix: Retire contract.ts's entity types in favor of lib/types.ts as the single domain model; rename any type still needed 'ContractRecord' or similar so it never shadows the global Record<K,V> utility type.

### Warnings
- [dead_code] src/lib/contract.ts reads as a frozen scaffold artifact whose function-signature types (`useAppDataFn`, `calculateMonthlyPayrollFn`, `analyzeUnpaidFn`, `formatCurrencyFn`, `useHapticFn`, `RouteState`) no longer match any real implementation in the app (actual: useAppData, calcMonthly/calculateMonthlyPayroll, analyzePay, formatWon/formatNumber, useHaptic, and a path-keyed RouteState in types.ts). Only `Record`/`PayrollEntry` are still imported, and only to harmful effect (see naming finding above). — Files: src/lib/contract.ts / Fix: Now that all packets are implemented, delete or archive contract.ts; if any type is still genuinely needed, move it into lib/types.ts under its real, currently-used name.
- [duplication] `currentYearMonth()` and `recentYearMonths(count)` are copy-pasted verbatim in Breakdown.tsx, Check.tsx, and Records.tsx; Home.tsx re-implements the same 'current/shift year-month' logic under different names (todayISODate/shiftYearMonth). — Files: src/pages/Breakdown.tsx, src/pages/Check.tsx, src/pages/Records.tsx, src/pages/Home.tsx / Fix: Extract a shared src/lib/date.ts with currentYearMonth/recentYearMonths/shiftYearMonth and have all four pages import from it.
- [duplication] Money formatting/parsing is scattered and reimplemented in four places with slightly different behavior: formatNumber/formatCurrency (lib/utils.ts, ko-KR locale), formatWon/parseWon (lib/analysis.ts, en-US locale for a Korean app), parseAmount (Check.tsx), and parseNumber (WorkplaceForm.tsx) — the latter two duplicate parseWon's digit-stripping logic almost exactly. — Files: src/lib/utils.ts, src/lib/analysis.ts, src/pages/Check.tsx, src/pages/WorkplaceForm.tsx / Fix: Consolidate into one currency module (single format + single parse function) and fix the accidental en-US/ko-KR locale inconsistency.

### Suggestions
- [duplication] Amount.tsx and CountUp.tsx duplicate the entire presentational wrapper (inline-block span, whiteSpace:nowrap, tabular-nums, Paragraph.Text + unit) with only the number-source logic (static vs animated) differing. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract a shared internal `NumericText` component that both Amount and CountUp render, parameterized only by the numeric value to display.
- [consistency] The 'toast driven by router location.state' pattern (incomingToast → useState(Boolean(...)) → useEffect to open) is hand-rolled independently in Records.tsx and Workplace.tsx, and RecordForm.tsx/AppDataProvider.tsx each hand-roll similar per-error-code toast state (quotaToastOpen, duplicateToastOpen, deleteFailToastOpen). — Files: src/pages/Records.tsx, src/pages/Workplace.tsx, src/pages/RecordForm.tsx, src/providers/AppDataProvider.tsx / Fix: Extract a `useRouteToast(state)` hook (and/or a generic `useToastQueue()` for outcome-driven toasts) to remove the repeated boilerplate.
- [naming] Duration formatting for worked time is implemented three times with two different names for the same behavior: `formatWorkedDuration` (RecordForm.tsx, Records.tsx) and `formatDuration` (RecentRecordsCard.tsx). — Files: src/pages/RecordForm.tsx, src/pages/Records.tsx, src/components/RecentRecordsCard.tsx / Fix: Move a single `formatWorkedDuration(minutes)` into lib/utils.ts and import it everywhere instead of redefining it per file.
- [dead_code] `cn()` in lib/utils.ts (className joiner) isn't referenced by any component shown — all components use inline `style` objects rather than className composition. — Files: src/lib/utils.ts / Fix: Confirm no consumer exists project-wide and remove it, or start using it consistently if class-based styling is intended somewhere.
- [structure] src/pages/__TdsGallery.tsx is a dev-only component tooling page living inside pages/, the only file in the tree using a double-underscore naming convention; every other page file maps 1:1 to a real route. — Files: src/pages/__TdsGallery.tsx / Fix: Move dev-only tooling views to a separate src/dev/ directory so pages/ stays strictly route-mapped (the DEV-only tree-shaking guard in App.tsx can remain unchanged).
